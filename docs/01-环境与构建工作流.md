## 2. 关键阻塞：中文路径导致仓颉构建失败

### 现象

```
cjpm build
→ cjpm.exe : Invalid unicode scalar value.
→ Error: failed to obtain package import information, please execute
     'cjc.exe -p C:\...\项目开发\...\src --scan-dependency' to check
→ Error: cjpm build failed
```

### 根因定位（对照实验）

| 实验条件 | 结果 |
|---|---|
| 无 `import` 语句的项目，中文路径 | ✅ 构建成功 |
| **含 `import` 语句**的项目，中文路径 | ❌ `Invalid unicode scalar value` |
| 含 `import` 语句的项目，**ASCII 路径** | ✅ 构建成功 |

**结论**：失败点精确定位在 `cjpm` 的**依赖扫描阶段**（`cjc -p <path> --scan-dependency`）。只要源码里有 `import`，且路径含非 ASCII 字符，就必然失败。

> ⚠️ 这解释了为什么最初的冒烟测试"看起来是成功的"——`cjpm init` 生成的 `main.cj` 不含 `import`，掩盖了问题。
> **教训：不要用无依赖的 hello-world 验证工具链。**

### 附带发现

- 调研报告称"cjpm 在 Windows 不支持中文路径"——**属实**，且比报告描述更严格（报告说"stdx/静态链接时触发"，实测是**只要 import 就触发**）。
- 尝试用 Windows 8.3 短路径绕过：`项目开发` 目录**没有生成 8.3 短名**，此路不通。
- 沙箱策略：仅会话工作目录 `...\项目开发` 与会话临时目录可写；父目录、`C:\Users\<user>\`、`D:\develop\` 均被拒绝。

## 3. 解决方案：源码在工作目录，构建在 ASCII 镜像区

会话临时目录 `$env:TEMP` 指向 `C:\Users\86178\AppData\Local\Temp\dsh-<随机>\`，**纯 ASCII 且可写**，可作为构建区。

```
C:\Users\86178\Documents\deepseek-harness\项目开发\   ← 源码唯一真相（含中文，可写）
    projects\<name>\  { cjpm.toml, src/, tests/ }
                    │
                    │  tools/cj.ps1 同步
                    ▼
C:\Users\86178\AppData\Local\Temp\dsh-*\cjbuild\<name>\   ← 纯 ASCII，实际构建处
```

### 用法

```powershell
powershell -ExecutionPolicy Bypass -File tools\cj.ps1 -Project <name> build
powershell -ExecutionPolicy Bypass -File tools\cj.ps1 -Project <name> test
powershell -ExecutionPolicy Bypass -File tools\cj.ps1 -Project <name> run
powershell -ExecutionPolicy Bypass -File tools\cj.ps1 -Project <name> bench
```

脚本会自动同步源码、设置 `PATH`/`CANGJIE_HOME`、执行 `cjpm`，并把覆盖率/基准等产物回收到 `projects\<name>\_out\`。

### 已知约束与注意点

1. **`cj.ps1` 必须保持纯 ASCII**。Windows PowerShell 5.1 对无 BOM 的 `.ps1` 按系统 ANSI（GBK）解码，UTF-8 中文注释会变乱码并导致解析错误。
2. **需要 `-ExecutionPolicy Bypass`**（当前用户策略为 `RemoteSigned`，脚本未签名）。
3. **`$env:TEMP` 是会话级的**，会话结束后镜像区可能被清理。源码始终以工作目录为准，不受影响。
4. **不要依赖 `_out/` 作为唯一产物存放地**；重要结果应显式复制回工作目录并提交。

## 4. 已实测可用的仓颉语言特性

以下均在 `projects/syntax_probe` 中编译并运行通过（`cjpm build success` / `cjpm test success`，1 passed）：

| 特性 | 实测写法 |
|---|---|
| 带载荷 enum | `public enum AgentMsg { \| Text(String) \| Compact(Int64, String) }` |
| 模式匹配 | `match (m) { case Text(s) => ...; case Compact(n, s) => ... }` |
| 接口 + 继承 | `public interface Policy {...}` / `public class P <: Policy {...}` |
| 构造函数 | `public init(limit: Int64) { this.limit = limit }` |
| struct 值类型 | `public struct Budget { public let tokens: Int64 ... }` |
| 字符串插值 | `"${n}:${s}"` |
| 泛型集合 | `ArrayList<Future<Int64>>()` |
| 并发 | `spawn { => expr }` 返回 `Future<T>`，`f.get()` 取结果 |
| 单元测试 | `import std.unittest.*` + `import std.unittest.testmacro.*`，`@Test` + `@Expect` |
| 测试运行 | `cjpm test` → 输出 PASSED/FAILED 汇总 |

### 语法踩坑记录（实测纠正）

| 以为 | 实际 | 说明 |
|---|---|---|
| `ArrayList.append(x)` | **`ArrayList.add(x)`** | 编译器报 `'append' is not a member of class 'ArrayList<...>'` |
| `import std.sync.*` 必需 | 单纯用 `spawn`/`Future` **不需要** | 未使用会告警 |

> 未使用变量/import 会产生 warning，建议在 `cjpm.toml` 的 `compile-option` 里按需处理，保持构建输出干净。
