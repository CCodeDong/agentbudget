# 实验管线接口：仓颉决策引擎 CLI

> 日期：2026-09-23 · 协议经实测验证
> 目的：让 Python 实验框架能调用仓颉库的调度决策，而不必链接仓颉运行时

---

## 1. 为什么需要这个接口

研究贡献有两个部分：

- **P2（仓颉库）**：预算感知的联合调度器 —— 这是要被测量和对比的**方法本体**
- **P3（实验框架）**：任务集、verifier、模型调用、指标采集 —— 用 Python 写效率最高

两者不能混在一起实现（否则测量的是 Python 的调度而不是仓颉的）。因此仓颉库暴露一个**进程级接口**，
Python 只负责驱动任务与采集数据，决策完全由仓颉代码做出。

这也正好落在方案早已预留的降级路径上："仓颉库编译为独立 CLI，PC 上跑实验，App 只做端到端演示"。

---

## 2. 协议

### 请求（stdin，每行一个）

```
<difficulty> <tier> <rttMs> <metered> <lan> <tokensSpent> <tokenCap> <cloudCallsLeft> [mode]
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `difficulty` | Float64 `[0,1]` | 该步难度估计（端侧小模型自评或启发式） |
| `tier` | `wifi\|cellular\|weak\|offline` | 广域网质量档 |
| `rttMs` | Int64 | 广域网 RTT |
| `metered` | `0\|1` | 是否计费流量 |
| `lan` | `0\|1` | **边缘推理节点是否在局域网内可达** |
| `tokensSpent` | Int64 | 本 episode 已消耗 token |
| `tokenCap` | Int64 | token 预算上限 |
| `cloudCallsLeft` | Int64 | 剩余云调用配额 |
| `mode` | `eager\|budget` | 选择基线或本方法（默认 `budget`） |

分隔符可用空格或 Tab；CR/LF 会被容错处理。

### 响应（stdout，每行一个，Tab 分隔）

```
<route>\t<msgForm>\t<toolStrategy>\t<toolTokens>\t<reason>
```

| 字段 | 取值 |
|---|---|
| `route` | `on-device` / `edge` / `cloud` |
| `msgForm` | `natural` / `summary` / `structured` |
| `toolStrategy` | `eager-all` / `eager` / `two-stage-top<k>` |
| `toolTokens` | 注入上下文的 token 估算 |
| `reason` | 人类可审计的决策理由 |

无法解析的行返回 `error\t<详情>` —— **大声失败，而不是静默给出错误测量值**。

## 3. 实测行为矩阵

用 6 组状态驱动，验证三层路由与预算降级：

| 输入 | route | msgForm | toolStrategy | reason |
|---|---|---|---|---|
| `0.2 wifi 20 0 1 500 8000 10` | **edge** | natural | eager | edge reachable on LAN |
| `0.9 wifi 20 0 1 500 8000 10` | **cloud** | natural | eager | hard step, wide-area viable, headroom left |
| `0.9 weak 1500 1 1 500 8000 10` | **edge** | natural | eager | **wide-area weak unusable; LAN survives** |
| `0.9 weak 1500 1 0 500 8000 10` | **on-device** | natural | eager | no remote tier viable |
| `0.2 wifi 20 0 1 7000 8000 10` | edge | **structured** | **two-stage-top3** | edge reachable on LAN |
| `0.9 wifi 20 0 1 500 8000 10 eager` | cloud | natural | eager-all | cloud preferred |

**关键验证点**：
1. 难度低时不浪费广域网调用 → 落到 edge
2. 难度高且有余量时才用 cloud
3. **弱网 + LAN 可用 → edge**（这是本方案相对现有工作的核心新增维度）
4. 弱网 + 无 LAN → 退回设备本地
5. **预算消耗 87.5% 时，工具策略切到两阶段加载、消息表示切到结构化** —— 预算驱动的联合降级生效

## 4. 两个必须遵守的环境约束（实测）

### 4.1 驱动方**不得**输出 UTF-8 BOM

PowerShell 5.1 通过管道传给本机进程时会给**第一行**加上 BOM（U+FEFF）。
表现为第一行解析失败：`error  parse failed on [﻿0.2 wifi ...]`（注意 `[` 后的不可见字符）。

**规避**：写输入文件时显式使用无 BOM 的 UTF-8：

```powershell
[System.IO.File]::WriteAllText($path, $content, (New-Object System.Text.UTF8Encoding($false)))
```

Python 侧则始终用 `encoding="utf-8"`（Python 默认不加 BOM）。

### 4.2 本沙箱下**不要用管道捕获子进程输出**

Dsh 沙箱禁止程序打开命名管道。Python `subprocess` 使用默认 `stdio='pipe'`
（以及 Node 的 `child_process`）会失败 `EPERM`。

**规避**：使用**文件重定向**，不要用管道。

```powershell
cmd /c ""<exe>" < "in.txt" > "out.txt" 2>&1"
```

已实测：6 行请求全部正确处理，退出码 0。
这也顺带绕开了 4.1 的 BOM 问题，因此**推荐把文件重定向作为标准调用方式**。

## 5. 推荐调用方式（给 Python 实验框架）

```python
import subprocess, tempfile, os, pathlib

EXE = r"C:\Users\86178\AppData\Local\Temp\dsh-XXXX\cjbuild\agentbudget4cj\target\release\bin\main.exe"

def plan_batch(requests: list[dict]) -> list[dict]:
    """requests -> decisions, via file redirection (no pipes: the sandbox forbids them)."""
    with tempfile.TemporaryDirectory() as d:
        inp = pathlib.Path(d) / "in.txt"
        outp = pathlib.Path(d) / "out.txt"
        lines = [
            f'{r["difficulty"]} {r["tier"]} {r["rtt_ms"]} {int(r["metered"])} '
            f'{int(r["lan"])} {r["tokens_spent"]} {r["token_cap"]} {r["cloud_calls_left"]} '
            f'{r.get("mode", "budget")}'
            for r in requests
        ]
        inp.write_text("\n".join(lines) + "\n", encoding="utf-8")   # utf-8, no BOM
        # shell redirection, not subprocess pipes
        subprocess.run(f'cmd /c ""{EXE}" < "{inp}" > "{outp}" 2>&1"', shell=True, check=False)
        out = outp.read_text(encoding="utf-8").splitlines()
    return [
        dict(zip(("route", "msg_form", "tool_strategy", "tool_tokens", "reason"), l.split("\t")))
        for l in out if l
    ]
```

> **性能提示**：CLI 是常驻进程，支持 stdin 连续输入。若驱动方能避免管道限制，
> 一次性喂入整批请求远优于每个请求启动一次进程。

## 6. 构建与调用

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
$cj = 'tools\cj.ps1'

# 构建（output-type = executable）
powershell -ExecutionPolicy Bypass -File $cj -Project agentbudget4cj build

# 可执行文件位置（构建镜像区）
#   $env:TEMP\cjbuild\agentbudget4cj\target\release\bin\main.exe
```

产出的可执行文件位于**构建镜像区的 ASCII 路径**下。
若需要固定位置供实验框架引用，可将该文件复制到工作目录（如 `projects/agentbudget4cj/bin/`），
但要记住：**它必须在 ASCII 路径下运行**，因为仓颉工程目录不能含中文。
