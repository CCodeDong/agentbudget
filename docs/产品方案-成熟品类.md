# 产品方案（第三版）：进入成熟品类

> 第二版被否的理由：**"用户不会用 / 没需求"** + **"不像个正经产品"**。
>
> 我想明白了病根：**我在发明新场景，而不是进入成熟品类。**
>
> 更新时间：2026-09

---

## 一、诊断：为什么之前的方案不像产品

| 我的方案 | 听起来像 |
|---|---|
| 「今天读什么」 | 一个**功能**（稍后读应用的子功能） |
| 「今天背什么」 | 一个**功能**（背单词应用的子功能） |
| 「空间告急」 | 系统自带功能的**重复** |
| 「本地知识库」 | 一个**技术演示** |

**共同问题：没有对照物。**

用户看到一个新场景，第一反应是"这谁用啊"，因为他不知道拿它跟什么比。
而"正经产品"的感觉来自：

> **用户已经在用的品类** + **我们能做得更好的那一点**。

**"稍后读"是成熟品类（Pocket、收趣），但"按可用时间切分文章"是我的发明。**
用户不关心这个发明，他关心"这跟 Pocket 比好在哪"。

## 二、方法转变

| | 旧方法 | 新方法 |
|---|---|---|
| 起点 | 想一个新颖场景 | **选一个成熟品类** |
| 研究的位置 | 整个产品 | **"比别人好在哪"** |
| 用户的认知负担 | 要理解新概念 | **已经知道这个品类干嘛的** |
| 风险 | 没人用 | 竞争，但品类有需求已被验证 |

**要回答的问题只有一个**：

> **我们的算法（有限额度下的自适应选择），能让哪个成熟品类明显做得更好？**

## 三、六条筛选线

每条都是硬性的，任一不过就淘汰：

| # | 筛选线 | 为什么 |
|---|---|---|
| 1 | **成熟品类**——应用市场里有大量同类且有人下载 | 需求已验证 |
| 2 | **零录入**——打开就能用，不需要用户先建数据 | 摩擦是产品杀手 |
| 3 | **纯离线可行**——不发网络请求也能完整使用 | 已定的约束 |
| 4 | **零 HMS 依赖**——不用无法验证的能力 | 你没有鸿蒙手机 |
| 5 | **算法是差异点**——不是"也能用"，是"明显更好" | 否则没理由做 |
| 6 | **2–3 个月能做完** | 时间现实 |

## 四、候选（成熟品类 × 我们的差异点）

### A. 「时间预算待办」

| | |
|---|---|
| **成熟品类** | 待办 / 时间管理（滴答清单、Todoist…） |
| **现有做法** | 给你一个列表，你自己挑 |
| **我们的差异点** | **你说"我只有 90 分钟"，它直接选出该做哪几件并排好** |
| **算法映射** | 有限时间预算下选择任务 —— **与 token 预算完全同构** |
| **零录入？** | ❌ 要用户录任务 |
| **可行性** | 高。纯逻辑，无依赖 |

---

### B. 「背单词 / 记忆卡」

| | |
|---|---|
| **成熟品类** | 单词卡（百词斩、Anki…） |
| **现有做法** | 固定算法（艾宾浩斯/SM-2），每天背固定数量 |
| **我们的差异点** | **"今天只有 10 分钟" → 按掌握度选出最该复习的 N 个** |
| **算法映射** | 掌握度 = **检索置信度**；背几个 = **注入深度** |
| **零录入？** | ✅ **可内置词库**（四六级等常见词表） |
| **可行性** | 高。但**发音需要 TTS（HMS，有风险）**，可先不做发音 |

---

### C. 「相册清理」

| | |
|---|---|
| **成熟品类** | 相册清理（腾讯手机管家等） |
| **现有做法** | 按大小/时间排序，让你自己删 |
| **我们的差异点** | **在"保留预算"下选出最该保留的**（相似照片、截图、模糊图） |
| **算法映射** | 预算下选择保留 —— **字面意义上的预算分配** |
| **零录入？** | ✅ 直接扫 |
| **可行性** | ⚠️ 需要**媒体读取权限**，审核更严；相似图判断需图像特征 |

---

### D. 「本地图片压缩」

| | |
|---|---|
| **成熟品类** | 图片压缩（大量在线工具 + 部分离线 App） |
| **现有做法** | 统一压缩比，或让你一张张调 |
| **我们的差异点** | **在体积预算下自适应分配**——重要照片少压，次要的多压 |
| **算法映射** | 预算下的自适应分配 |
| **零录入？** | ✅ 选图即可 |
| **可行性** | 中。需要媒体权限；解码编码在 ArkTS 里偏慢 |

---

### E. 「稍后读 + 时间切分」

| | |
|---|---|
| **成熟品类** | 稍后读（Pocket、收趣、微信收藏） |
| **现有做法** | 存起来，按时间排 |
| **我们的差异点** | **"我有 10 分钟" → 给你正好能读完的部分** |
| **算法映射** | 保留哪些段落 = 注入深度；信息密度 = 置信度 |
| **零录入？** | ⚠️ 要分享/导入文章（但只是一步操作） |
| **可行性** | 高。零权限、零依赖 |

---

### F. 「离线文档扫描 / OCR 整理」

| | |
|---|---|
| **成熟品类** | 扫描全能王等 |
| **差异点** | 弱——OCR 是 HMS 能力，我们没有 |
| **结论** | ❌ **淘汰**（违反筛选线 4） |

## 六、我推荐 B「背单词」，理由

**1. 它是唯一"零录入 + 零权限 + 零网络 + 零 HMS"四项全过的。**
内置四六级词库 → 用户下载就能用，不需要做任何准备。

**2. 差异点是真的**：
主流单词应用的普遍做法是"每天固定 N 个"。
我们做**"你给多少时间，我挑最该背的"**——这是用户能立刻感知的差别。

**3. 算法映射最干净**：

| 论文概念 | 产品里的东西 |
|---|---|
| **检索置信度** | **你对这个词的掌握度** |
| **工具注入深度** | **今天背几个** |
| 预算分配 | 10 分钟怎么分 |
| **自适应 vs 固定规则** | **正是 §6.6（反面）与 §6.7（正面）的对照** |

**4. 它天然需要一个"高级"页放我们的调度细节**——课程展示有了，主页依然干净。

**5. 品类极其成熟**——用户一看就知道这是什么，不存在"这谁用啊"。

### 需要如实说明的两个风险

1. **发音（TTS）依赖 HMS**，有 A2A 同款崩溃风险 → **建议第一版不做发音**，
   或做成可选功能并做好降级
2. **竞争激烈**——但我们的目标是通过审核并体现研究，不是打赢百词斩
