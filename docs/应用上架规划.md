## 一、现状诊断：我们有什么，缺什么

| 项 | 现状 | 上架要求 | 差距 |
|---|---|---|---|
| 应用能构建、签名、安装、运行 | ✅ 已实测 | 必须 | — |
| `.app` 包能打出 | ✅ 已实测（134 KB） | 必须 | — |
| **发布签名** | ❌ 用的是 `debugKey` 调试证书 | 发布证书 + Profile | **1–2 天** |
| **应用对用户有价值** | ❌ 是研究控制台，术语满屏 | 功能完整、有明确用途 | **1–2 个月** |
| 图标 / 截图 / 简介 | ❌ 无 | 必须 | 1 周 |
| 隐私政策 / 用户协议 | ❌ 无 | 需**可公开访问的 URL** | 1 周 |
| **不联网** | ✅ **实测：不发任何网络请求** | — | **可能豁免备案** |
| 软著 | ❌ 无 | **待确认是否必需** | **30–60 工作日** |
| 开发者实名认证 | ✅ 已完成 | 必须 | — |

### 一个真实优势

**实测确认：应用不发起任何网络请求**，只申请了 `GET_NETWORK_INFO`
用来读取当前网络档位（决定"本地/边缘/云"的调度）。

- **只有 1 个权限**，且是读取类，不涉及用户隐私数据
- **无服务端**，不上传任何数据
- → **很可能豁免 App 备案**（备案针对"互联网信息服务"，我们是纯单机）

> ⚠️ **但必须向华为确认**。AppGallery 可能对**所有**应用统一要求备案号。

## 二、关键路径：三件事决定成败

```
                    ┌─────────────────────────────┐
                    │  ① 软著：30–60 工作日        │  ← 最长，且可能被要求
                    │     必须在第 1 周启动          │
                    └─────────────────────────────┘

                    ┌─────────────────────────────┐
                    │  ② 应用要有真功能            │  ← 工作量最大
                    │     现在会被以"仅演示"拒审     │
                    └─────────────────────────────┘

                    ┌─────────────────────────────┐
                    │  ③ 发布签名：1–2 天          │  ← 不需等审批
                    │     现在就能做                │
                    └─────────────────────────────┘
```

**① 是时间炸弹**：30–60 个工作日 ≈ 1.5–3 个月 ≈ **你的全部剩余时间**。
如果它是必需的，"这个月启动"就已经晚了。

**② 是工作量大头**：不是包装，是补功能。

**③ 最简单，且与 ①② 完全独立**，可以今天就做完。

## 三、产品定义：这是最重要的决策

**现状问题很直白**：打开应用是「边端多智能体编排」，上面写着
`edge` / `structured` / `two-stage-top3`。按"运行一步"只做一个本地调度计算，
**不产生任何对普通用户有用的东西**。

应用市场明确会拒"功能不完整（如仅演示）"的应用。

### 手机形态上可用的 AI 能力（已从 SDK 元数据核实）

| 能力 | phone | 说明 |
|---|---|---|
| `DataAugmentation.Retrieval` | ✅ | **本地向量检索** |
| `DataAugmentation.KnowledgeProcessor` | ✅ | **本地知识处理/索引** |
| `AI.OCR.TextRecognition` | ✅ | 图片文字识别 |
| `AI.SpeechRecognizer` / `TextToSpeech` | ✅ | 语音输入输出 |
| `AI.NaturalLanguage.TextProcessing` | ✅ | 文本处理 |
| `AI.CANN.LLMEngine` | ❌ | **不能自部署大模型**（2in1 才有） |

**关键：手机不能跑大模型，但能做真·本地检索。**

### 三个候选方案

#### 方案 A：「AI 省流助手」—— **零平台风险，推荐保底**

用户把要发给 AI 的长文本粘进来，应用用预算策略压缩，显示省了多少，一键复制。

| 维度 | 评估 |
|---|---|
| 用到的研究 | **直接就是核心算法**（摘要截断、结构化编码、预算策略） |
| 技术风险 | **极低**——只用标准 ArkTS，不依赖任何 HMS 能力 |
| 能否离线 | ✅ 完全离线，**一个请求都不发**（省流工具自己不耗流量） |
| 实现难度 | 低。核心逻辑已存在（`MessageCodec` / `BudgetPolicy`） |
| 用户价值 | 中。面向经常用 AI 的人 |
| 审核风险 | 低。工具类应用，功能完整、用途明确 |

#### 方案 B：「本地知识助手」—— 价值更高，但有硬障碍

把你的文档索引到本地，离线也能检索；高级页由预算调度决定检索深度。

| 维度 | 评估 |
|---|---|
| 用户价值 | **高**——隐私 + 离线可用 |
| 用到的研究 | 很贴切（检索深度 = 工具注入 = 我们研究的第一维度） |
| **技术风险** | **高**——`DataAugmentation.*` 属于 HMS kit，**很可能和 A2A 一样需要 HSP，缺失时会加载期崩溃** |
| **验证障碍** | **你没有鸿蒙手机**（模拟器无 HMS Core，真机是 2in1 而该能力标注 phone/tablet） |

#### 方案 C：「网络质量助手」—— 最常规，但研究味最淡

显示网络质量、流量使用，建议当前网络适合做什么。

| 维度 | 评估 |
|---|---|
| 审核风险 | **最低**（最像常规工具类应用） |
| 用户价值 | 中低（同类应用很多） |
| 与研究的联系 | **弱** |

### 我的建议

**先做方案 A，有余力再并入 B 的检索能力。**

理由：

1. **"上架"是硬要求，不能赌。** 方案 A 零平台依赖，一定能做出来。
2. **方案 B 的验证前提你已经不具备**（没有鸿蒙手机），而验证失败意味着全部重做。
   在只剩 2–3 个月、还要同时办软著的情况下，这个风险不该承担。
3. **方案 A 的研究含量并不低**——它的核心引擎就是论文里的那些策略，
   而且它把研究结论变成了用户能看见的数字（"省了 62%"）。

> **不要让"上架"和"研究"互相消耗。**
> 方案 A 是两者都满足的最小可行交集。

## 四、时间线（假设本周启动，剩 13 周）

```
第 1 周  ├─ ★ 申请软著（若确认必需）—— 最长，必须最先启动
         ├─ ★ 配置发布签名（AGC 建应用 + 证书 + Profile）
         ├─ 向华为确认：是否必须软著？是否必须备案？
         └─ 确定产品方案（A / B / C）
第 2 周  ├─ 隐私政策 + 用户协议（用 GitHub Pages 托管成可访问 URL）
         └─ 开始界面改造
第 3–5 周├─ 界面改造 + 功能实现
         └─ 图标、截图、简介文案
第 6 周  ├─ 内部测试，修崩溃
         └─ 正式构建发布版 .app
第 7 周  ├─ 提交审核
第 8–9 周├─ 应对驳回、返工、重新提交
第 10 周 └─ 上架 ✅
第 11–13周 ─ 课程报告 / PPT / 答辩（余量）
```

**余量约 3 周**——比"只提交"的方案紧，但仍可行，前提是**第 1 周把两件事都启动**。

## 五、立刻要做的四件事（第 1 周）

### 1. 问华为：两个必须确认的问题

在[华为开发者社区](https://developer.huawei.com/consumer/cn/forum/)提问，原话可以这样写：

> **问题一**：个人开发者上架 HarmonyOS 应用（非游戏类，纯本地功能，**不发起任何网络请求**），
> 是否强制要求**软件著作权证书**？
>
> **问题二**：同上应用，**无服务端、不联网**，是否仍需完成 **App 备案**才能上架？

**这两个答案决定后面所有安排。**

### 2. 配置发布签名（不需等任何人）

[AppGallery Connect](https://developer.huawei.com/consumer/cn/service/josp/agc/index.html)：

1. **我的应用 → 新建应用**（包名 `com.xjtu.agentbudget`，**一旦确定不能改**）
2. **证书、Profile 管理 → 证书 → 新增**：生成 CSR → 上传 → 下载 `.cer`
3. **Profile → 新增**：绑定包名 → 下载 `.p7b`
4. 本地生成发布密钥库 `.p12`

> ⚠️ **`.p12` 丢失 = 应用永远无法更新**。备份，且不进 git。

### 3. 准备隐私政策

需要一个**可公开访问的 URL**。最省事的做法：**用仓库的 GitHub Pages**
（我们已经把项目放上 GitHub 了）。

内容至少包含：收集什么数据（**答案是几乎不收集**）、如何使用、如何删除、联系方式。

> **诚实反而简单**：我们只读网络状态、不上传任何数据——
> 这比大多数应用都干净，如实写即可。

### 4. 决定产品方案

**这是你的决策**，因为涉及课程展示重点。我推荐 A，但需要你确认。
