## ⚠️ P8 的结论与原稿相反，必须按这张图讲

**成本**：token 降 50–70%，所有套件都成立。

**成功率**：多数持平或略降（90–100%），**不是全面持平**。

**并且有一个真实失败点**：
在 `results_multiturn` 与 `results_sumbudget` 两个套件上，
`budget_util = 0.45` 这一档，本方案成功率跌到 **0% / 60%**，基线是 100%。
**原因尚未定位。** PPT 上写"待定位的缺陷"，不要编原因。

**为什么这反而是加分项**：
这个临界点失败正好落在 P9"误差传导"的议题上——预算信号在临界区附近，
估计误差会把决策推到错误一侧。**主动讲出来比藏起来强。**

## 做 PPT 前必须改的四处

1. **周制**：原稿"16 周制、第 6 周" → **12 周制、第 7 周**
2. **行数口径**：`1,678 行` → **`1,678 行（含空行）/ 1,527 行（去空行）`**
3. **状态语态**：统一为【已完成】/【进行中】/【未开始】
4. **不严谨表述**："唯一""全部" → 改为可核实限定
