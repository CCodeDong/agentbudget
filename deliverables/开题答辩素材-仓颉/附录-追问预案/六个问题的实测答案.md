> PPT 附录列了 6 个预期被追问的问题。
> **这 6 个问题我们现在都能用实测数据回答**，而不只是"我们打算……"。

## Q1｜为什么这个课题要用仓颉，而不是 Python？

**PPT 的原答**（很好，保留）：可测量 —— 确定性断言 + 覆盖率报告。

**我们补充的实测依据**：

| PPT 的说法 | 实测 |
|---|---|
| "用 `@Test` / `@Expect` 写确定性的单元测试" | ✅ **29 个测试全部通过**（`PASSED: 29, SKIPPED: 0, ERROR: 0`） |
| "用 `cjcov` 产出覆盖率报告" | ✅ **行 88.6% / 分支 66.8%**（库整体） |
| "不依赖模型、不依赖网络" | ✅ **`budget.cj` 与 `scheduler.cj` 零 `std` 导入**，全库零外部依赖 |

## Q2｜"三个维度三个信号"，凭什么认为是对的？

**PPT 的原答**（非常好，**不要改**）：

> "我们现在还**不认为**它是对的——这正是这学期要验证的东西。……
> **如果第二个实验也不成立，那我们的结论就是'两个信号都不行'，这同样是一个结果。**"

**这个回答是整份 PPT 里最稳的一条**——它把主张降格为待验证命题，无懈可击。

**建议不要用实测结果去"加强"它**，那会把"待验证"变成"已证明"，反而削弱开题的性质。

---

## Q3｜和已有的工具注入方案有什么区别？

**PPT 的原答**：机制接近，区别在测量。

**我们有的硬证据**：

我们核实过一篇同机制的工作（Tool Attention，arXiv:2604.21816），
其**原文自述**：

```
"End-to-end figures for task success, latency, cost, and reasoning quality
 are reported as projections derived from the measured token counts...
 they are not measured on live LLM agents"
```

**这是"已有工作把端到端效果留成推断"的直接引文**，来自原文，不是我们的推测。

> 加上这句引用，Q3 的回答就从"我们认为"变成"原文如此"。

## Q4｜为什么把消息形式和执行位置也放进同一个题目？

**PPT 的原答**：三件事同时发生、互相抢预算。

**我们补充的实测依据**：

截断式摘要的实验显示——**"省"与"完整"是互斥的**：

| 预算 | 消息形式 | 结果 |
|---|---|---|
| ≤ 60 字符 | 更便宜 | **验证器拿不到参数 → 失败** |
| ≥ 80 字符 | 恢复完整 | **成本追平结构化编码** |

**即：不存在"既完整又明显更便宜"的预算点。**

这正是 Q4 说的"互相抢预算"的**具体证据**——消息形式的选择不是一个独立的旋钮。

## Q5｜十周时间够吗？如果做不完怎么办？

**PPT 的原答**（很好）：主线优先，砍实验不砍主线和测试。

**我们补充的实测依据**：

**优先级排序是对的，因为我们实际验证过"主线可以独立于实验存在"**：

| | 主线（库本体） | 实验 |
|---|---|---|
| 体量 | **1,195 行**（不含测试） | 实验框架与数据 |
| 依赖 | **零外部依赖** | 依赖主线 |
| 可独立交付 | ✅ 可以 | ❌ 不行 |

**"一个测过的库，比一个跑了实验但没测过的库更有交付价值"——这句话有依据**：
库本体不依赖实验，实验反过来依赖库。

## Q6｜这个库最后怎么证明它有用？

**PPT 的原答**：提供命令行入口，打印每一步决策与理由；验收标准是"每条决策都能对上一个可断言的测试用例"。

**我们补充的实测依据**：

**这个命令行入口已经存在并有实录**（见 [`../P10-预期成果/仓颉演示实录.md`](../P10-预期成果/仓颉演示实录.md)）：

- 给定预算、网络档位、任务，它打印完整调度决策
- 输出包括：执行位置 / 消息形式 / 工具策略 / 决策理由 / token 开销 / 验证结果

**并且**：应用侧（ArkTS 移植实现）与本库做了**全任务集差分测试**——
**30 条查询，30/30 输出一致**。

> 这回答了"怎么证明它有用"的另一半：**不只是"能跑"，而是"两个实现行为一致"**。

## 汇总：哪些该用，哪些不该用

| 问题 | 建议 |
|---|---|
| Q1 为什么用仓颉 | ✅ **可以用实测数据强化** |
| Q2 凭什么认为对的 | ⚠️ **保持原答，不要用结果去"加强"** |
| Q3 与已有工作的区别 | ✅ **可以引用原文自述** |
| Q4 为什么放一起 | ✅ 可以用截断实验的证据 |
| Q5 时间够不够 | ✅ 可以用"零依赖"强化 |
| Q6 怎么证明有用 | ✅ 可以用差分测试强化 |

**Q2 是唯一一个"不要动"的**——它现在的答法把主张保持在"待验证"状态，
这正是开题答辩应有的姿态。
