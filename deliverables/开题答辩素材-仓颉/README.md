## 四、素材包里没有的东西（诚实说明）

| 缺什么 | 说明 |
|---|---|
| **真实的推理端点数据** | 全部数值来自自己写的模拟端点。论文 §7.1 自述为最大效度威胁 |
| **真机运行** | 应用在**模拟器**上跑通过，真机（2in1）未成功运行 |
| **`main.cj` 的测试覆盖** | 命令行入口覆盖率为 0（单测不驱动 CLI，由演示实际执行） |
| **与真实大模型的对比** | 没有真实模型参与，因此"省了多少 token"是在模拟条件下测的 |

**这些在开题答辩里应当如实说明**——开题阶段承认限制是正常的，
但**如果宣称已完成的实验用了真实模型，后面会被追问数据**。

## 五、⚠️ 最重要的一节：开题答辩该怎么表述

**开题答辩的性质是"论证这个题目值得做、我们做得成"，不是"汇报已完成的工作"。**

所以**不能**说"我们都做完了"——那会让老师问"那你开题干什么"。

### 建议的表述框架

| 我们实际有的 | 在开题里应当说成 |
|---|---|
| 已实现的调度器库 | "**前期技术验证**中，我们已经实现了一个原型调度器，验证了思路可行" |
| 已完成的正反实验 | "我们**初步跑通了判定方法**，证明这套对照实验是可行的" |
| 已核实的 18 条文献 | "我们已完成文献调研，识别出了这个空位" |
| 29 个测试 / 88.6% 覆盖率 | "原型上已经建立了测试与覆盖率度量，说明**这件事是可测量的**" |

### 核心逻辑

> **不要展示"我们做完了"，要展示"我们证明了这件事做得成"。**

这两句话事实相同，但**前者会让开题失去意义，后者正好是开题要回答的问题**。

**P7/P8 尤其要注意**：P8 写的是"我们**打算**证明"。如果直接给出实验结果，
就变成了"已结题"。建议表述为：

> "我们已经设计好了这对实验，**并在原型上初步验证了判定标准是可用的**——
> 正式实验将在本项目周期内完成。"

## 六、一句话总结

**这个素材包里有的是"能力证明"，不是"结题报告"。**

用它的正确方式是：**证明"这件事我们做得成"**——
因为已经有原型、有测试、有覆盖率、有踩过的坑和解法。
