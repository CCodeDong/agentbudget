### 第一部分：为什么做（3 页）

**P3 ｜痛点：手机上的资料"存得进去，找不出来"**
- 资料分散在备忘录 / 聊天记录 / 截图 / PDF
- 系统搜索大多只匹配标题和文件名，**进不去正文**
- 结果：只记得"好像在哪写过这个词"，却找不到
- 【已验证】示例资料 109 字，切成 1 个片段即可正文级命中

**P4 ｜现有方案为什么不够**
- 云端笔记类：能搜，但**要联网、要账号、数据在别人服务器**
- 本地文件搜索：能离线，但**不索引正文**（或只索引文件名）
- 系统相册 / 备忘录：各自为政，**不能跨来源检索**

> 保留原稿 P5 的调研表，但**必须补一列"能不能离线"**——
> 这是差异化所在，不写就体现不出来。

**P5 ｜技术背景：同一套代码，两台设备能力相反**
- 【已验证】实测结果：

  | 能力 | MateBook Pro（2in1 / API 23） | 模拟器（phone / API 26） |
  |---|---|---|
  | 文字识别 | 可用 | **不可用** |
  | 智能体框架 | **不可用** | 可用 |

- 结论：**不能假定能力存在，必须探测 + 降级**
- 这一页是原稿完全没有的，也是本课程最有说服力的一页：**它是实测的，不是推演的**

### 第二部分：我们的三个设计判断（3 页）

**P6 ｜判断一：检索深度不能固定，要看得分分布**
- 固定 k 的问题：区分度高时返回太多噪音，区分度低时又不够
- 做法：**看得分分布有没有明显断层**，断层前全留，平坦则取上界
- 【已验证】150 条真实语料查询：

  | 策略 | 召回率 | MRR | 精确率 | 平均返回 |
  |---|---|---|---|---|
  | 固定 k=3 | 100% | 0.970 | 62.0% | 3.0 |
  | **自适应** | **100%** | **0.970** | **84.7%** | **1.9** |

  **同样的召回与排序质量，精确率高 22 个百分点，少返回 37% 条目。**

**P7 ｜判断二：同一段话不该返回多次**
- 分块有重叠，关键词一出现就同时命中相邻几块 → 用户看到"同一段话"重复
- 做法：**合并同文档中重叠或首尾相接的命中**
- 【已验证】同文档重复查询 **35 → 11（-69%）**，召回率与 MRR 不变
- 一个刻意的取舍：**得分取最高分不累加**（累加会把分块副作用当相关度）

**P8 ｜判断三：识别质量要看"认得够不够多"**
- 【已验证】12 种退化条件：

  | 条件 | 召回 | 精确 |
  |---|---|---|
  | 清晰 / 模糊 / 低对比 / 旋转 / 小字 / 楷体 | 100% | 100% |
  | 行楷（近手写） | 98% | 98% |
  | 强模糊 | 93% | 93% |
  | **小字 + 模糊** | **28%** | **100%** |

- **关键观察：精确率从未低于 100%，除非召回同步下降**
  → OCR 的失败方式是**漏认**，不是**错认**
  → 所以有效性信号是"认得够不够多"，不是"认得准不准"

> 这一页是原稿**最缺**的：老师说的"无法核实"，在这里变成"我们自己量化过了"。

### 第三部分：怎么保证数据不出设备（2 页）⭐ 回应批评④

**P9 ｜零权限不是口号，是可核实的**
- **不申请任何系统权限**，包括网络权限
- 【已验证】安装后「设置 → 应用 → 权限」列表为空
- 那"选图识别""导入文件"怎么做到不需要权限？
  - 用**系统选择器**，不是权限：系统界面取图/取文件，应用只拿到**你选中的那一个**
  - 系统提示语："应用仅可访问您选定的图片和视频，无法访问图库其他内容"
- **取舍**：调相机会要 CAMERA 权限 → **宁可少一个入口，也不放弃零权限**

**P10 ｜数据全生命周期**
- 存放：应用私有沙箱（`/data/app/el2/.../com.xjtu.offlinelib/`）
- 持久化：**只存原始文档，索引启动时重建**（索引格式变化不会让旧档失效）
- 【已验证】强制杀进程后重启，资料仍在（示例与用户新增都验证过）
- 卸载：**数据一并删除、不可恢复**——这是"不出设备"的必然结果，必须在隐私政策里明说
- 代码中**不包含任何网络请求**
