## 四、软件说明（这几栏字数有上限，下面直接复制）

### 4.1 开发目的

```
为解决手机端个人资料分散、正文无法检索的问题，开发一款完全离线的个人资料库工具。
现有系统搜索多只匹配标题或文件名，不进入正文；而把笔记上传云端又与用户对隐私的
诉求相冲突。本软件在设备本地完成切词、索引与检索，不申请任何网络权限，
在保证隐私的前提下提供正文级全文检索能力。
```

### 4.2 面向领域 / 行业

```
通用工具软件；面向教育、科研与个人知识管理场景。
```

### 4.3 软件的主要功能

```
一、资料导入：支持以粘贴文本方式将笔记、讲义、摘录存入本机资料库，
导入时自动切分片段并建立倒排索引。
二、全文检索：按 BM25 算法对全部片段打分排序，命中的关键词在结果中高亮显示，
并直接定位到原文位置。
三、检索深度自适应：根据候选结果得分的分布是否出现明显断层，自动决定返回条数，
用户也可切换为固定条数模式作对照。
四、决策解释：每次检索后显示返回条数、深度来源、受限因素与候选数量，
使用户理解检索结果的产生依据。
五、资料管理：列出全部已入库文档，支持逐条删除；删除采用增量方式，
仅标记失效片段并在比例超限时自动整理。
六、图片导入与文字识别：集成系统文字识别能力，可从系统相册选择图片并将其中文字转为可检索文本（采用系统相册选择器，不申请相机权限），
并按识别质量给出"收下/重拍/丢弃"的分档建议。
七、设备能力探测：查询当前设备对文字识别、端侧检索、视觉基础等能力的支持情况，
据此决定启用哪些特性。
八、设备内自测：在设备上直接运行 14 项检查并逐条显示结果，
覆盖切词、分块、打分、存储与流水线全流程。
```

### 4.4 技术特点

```
一、中文切词不依赖词典：采用"单字＋二元组"切词，既以单字保证召回，
又以相邻两字组合保证区分度，无需引入分词词典，避免词典体积与未登录词问题。
二、BM25 排序：参数取 k1=1.5、b=0.75，同时考虑词频饱和与文档长度归一化，
避免长文档因字数多而获得不当优势。
三、墓碑式增量删除：删除文档时不重排索引，而将片段标记为失效，
墓碑占比超过 20% 时自动整理一次，使删除开销与删除量成正比而非与库规模成正比。
四、索引与持久化分离：持久化只保存原始文档，索引在启动时重建，
使索引格式变更不会导致旧存档失效。
五、文字识别以接口形式接入：真实识别实现由上层注入，
在缺少该能力的设备上软件仍可正常启动并使用其余功能。
六、完全离线：不申请任何系统权限（含网络权限），全部检索在设备本地完成。
```

## 五、上传什么（这是最容易被问的一节）

登记系统的上传位一共 **3 个**，外加**条件性**的 1 个。

### 5.1 必须上传的三个

| # | 上传位 | 传哪个文件 | 说明 |
|---|---|---|---|
| 1 | **源程序** | `源代码文档-离线资料库软件V1.0.pdf` | **优先用 PDF**（见下） |
| 2 | **文档** | `软件说明书-离线资料库软件V1.0.pdf` | 同上 |
| 3 | **身份证明** | 你的身份证正反面 | **你准备**，见 5.3 |

### 5.2 为什么优先传 PDF

| 格式 | 风险 |
|---|---|
| **PDF** | ✅ 排版固定，页数/行数不会因对方环境变化，**推荐** |
| `.docx` | ⚠️ 换台机器打开可能因字体缺失而重排，导致每页行数变化 |

我们已经生成了两份 PDF，并**用 pypdf 核对过实际页数**：

| 文件 | 页数 | 核对 |
|---|---|---|
| 源代码文档 PDF | **48 页** | ✅ 生成时断言与实际一致 |
| 软件说明书 PDF | **5 页** | ✅ |

> 如果系统只接受 Word，`.docx` 两个文件也在同目录里，直接传即可。

### 5.3 身份证明的具体要求

| 项 | 要求 |
|---|---|
| 内容 | 身份证**正反面**，两面缺一不可 |
| 清晰度 | 姓名、号码、有效期必须清晰可读，不能反光、不能裁切 |
| 格式 | JPG / PNG / PDF，按系统要求 |
| 命名 | 建议 `身份证-姓名-正面.jpg` / `-反面.jpg` |
| 常见退回 | 四面裁切不完整、有手指遮挡、反光看不清号码 |

### 5.4 条件性材料（只有以下情况才需要）

| 情况 | 需要额外上传 |
|---|---|
| 合作开发（本项目**未选**） | 需要《合作开发协议书》，三人手写签字。我方已选独立开发，**此项不需要** |
| 委托开发 | 委托开发合同 |
| 职务作品 | 单位出具的权利归属证明 |

> 如果选「独立开发」，**这一项完全不需要**，这也是推荐独立开发的原因之一。

### 5.5 不需要上传的东西（别去找）

| 东西 | 为什么不用传 |
|---|---|
| 申请表本身 | 在系统里在线填写，系统自动生成，不需要单独上传 |
| 官费凭证 | 在线支付，系统自动记录 |

| 编译产物（HAP / exe） | 软著登记**不要求**提交可执行文件 |
| 测试报告 | 不强制要求 |

## 六、提交流程

1. 注册 / 登录 [中国版权保护中心](https://www.ccopyright.com.cn/) 网上服务大厅
2. 选择「软件著作权登记」→「新增申请」
3. 按上面的字段逐项填写（第四节的四段文字直接复制）
4. 上传：源程序 PDF、说明书 PDF、身份证明
5. 选择办理方式：
   - **普通件**：250 元，20–30 个工作日
   - 加急件：800–3000 元，7–30 个工作日
6. 缴费并提交

> **建议先按普通件提交**。如果第 6 周（约 2026 年 12 月上旬）还没下来，
> 再考虑加急或补办——那时离期末还有时间。
