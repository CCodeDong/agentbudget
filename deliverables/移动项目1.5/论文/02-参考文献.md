### [A2] Tscg：互补路线的最近工作

Furkan Sakizli.
**Tool-Schema Compression Enables Agentic RAG Under Constrained Context Budgets.**
arXiv:2605.26165. <https://ar5iv.labs.arxiv.org/html/2605.26165>
代码：<https://github.com/SKZL-AI/tscg>

> 摘要与正文取到的事实：28 工具 / 8K·16K·32K 三种预算 / 14 个模型 / 6,566 次受控调用 /
> HotpotQA 外部验证；Tscg 压缩节省 schema token 44–50%；8K 下 JSON schema **溢出**窗口
> （约 11,000 token）导致平均 EM 2.6%，压缩后 +20.5pp；32K 下两格式无差异；
> 前沿测试中 JSON 在约 494 个工具时溢出，压缩格式在 800 个工具以上仍可用。
> 其相关工作明确把 tool selection 称为"互补"，并指出它
> *"sacrifices awareness of unselected tools"*。
>
> **正文引用处**：§2.6 第 2 行、§2.6 的两点诚实说明。
> **本文的差异**：它压**格式**、保留感知；本文选**工具**、牺牲感知——
> 而本文量化了这个牺牲（§6.3：损失 100% 来自检索漏选）。

### [A7] Tool Attention：机制与本文实质相同，但只测 token（已读摘要）

Anuj Sadani, Deepak Kumar.
**Tool Attention Is All You Need: Dynamic Tool Gating and Lazy Schema Loading for
Eliminating the MCP/Tools Tax in Scalable Agentic Workflows.**
arXiv:2604.21816 (2026-04-23). <https://arxiv.org/abs/2604.21816>
代码：<https://github.com/asadani/tool-attention>

> 摘要核实到的事实：
> - 机制三部分：(i) 句嵌入的 **Intent Schema Overlap (ISO)** 打分，
>   (ii) 状态感知门控（前置条件与访问范围），
>   (iii) **两阶段懒加载器——上下文中保留紧凑摘要池，只为 top-k 门控工具提升完整 JSON schema**。
> - 结果：模拟 120 工具 / 6 服务器基准上，每轮工具 token 降低 **95.0%（47.3k → 2.4k）**，
>   上下文利用率 24% → 91%。
> - 原文对"10k–60k"的归属：*"practitioner reports place between roughly 10k and 60k tokens"*
>   ——**是实践者报告，不是作者实测**。正文引用时必须保留这一归属。
> - 原文自述：*"End-to-end figures for task success, latency, cost, and reasoning quality
>   are reported as projections derived from the measured token counts...
>   **they are not measured on live LLM agents**, and we mark projected values explicitly"*。
>
> **⚠️ 记录一次作者自己的过度更正**：
> 本稿曾写"端到端结果为 projection"，并在一次核实中**因检索不到该说法而将其删除**，
> 理由是"无来源的归因"。本轮读到摘要后发现——**该说法确实出自原文，我删错了**。
> 现已恢复，并补上原文的直接引语作为依据。
>
> **教训**：删除一条自己无法立即验证的表述，与保留它同样需要证据。
> "检索不到"不等于"不存在"，尤其是在只做了一轮检索的情况下。
> 正确的做法是标记为待核实（如本文件 B0/B 的分法），而不是直接删除。
>
> **与本文的关系（已同步到正文 §1.2、§2.3、§2.6）**：
> 机制实质相同；差异在于**它只测量 token，把端到端效果留作 projection**。
> 本文实测了该机制的准确率代价，并证明 **100% 来自检索漏选**（§6.3），
> 进而给出控制它的信号（§6.6–§6.7）。**本文测的是它只能预测的东西。**

### [A8] EcoAgent：定位重叠度最高的一项工作

**EcoAgent: An Efficient Device-Cloud Collaborative Multi-Agent Framework for Mobile Automation.**
AAAI 2026. DOI: 10.1609/aaai.v40i35.40230.
<https://ojs.aaai.org/index.php/AAAI/article/view/40230>

> **已读摘要，事实核实如下**：
> - 现状判断：移动多智能体系统**主要部署在云端**，导致高时延与高运营成本；
>   直接做设备–云协作"nontrivial"，因为 (1) 云侧验证需上传手机截图、损害隐私，
>   (2) 缺少设备到云反馈的开环协作。
> - 方案：闭环设备–云协作多智能体框架；云端 Planning Agent 用 **Dual-ReACT**，
>   使**设备侧验证**与轻量反馈成为可能；设备侧 Observation Agent 用
>   **Pre-understanding Module 把屏幕内容总结为简洁文本**，
>   *"significantly reducing token usage and device-cloud communication overhead"*。
> - 评测：**AndroidWorld**；匹配纯云智能体的成功率，同时降低资源消耗与响应时延。
> - 作者：Biao Yi, Xueyu Hu, Yurun Chen, Shengyu Zhang（浙江大学）,
>   Hongxia Yang（香港理工大学）, Fan Wu（上海交通大学）。
>
> **与本文的重叠（此前被低估）**：同为"设备–云协作 + 多智能体 + 移动 +
> 降低 token 与通信开销"。原描述仅写"端侧/端云协同智能体"，掩盖了重叠度。
>
> **与本文的差异（三条，已同步到正文 §2.6）**：
> 1. **两层 vs 三层**：它没有局域网边缘层。
> 2. **网络质量不入决策**：其结构由隐私与反馈闭环驱动，摘要未涉及链路质量。
> 3. **压缩的对象与方式不同**：它压缩**观察**（屏幕内容→简洁文本）且用**学习到的摘要模块**；
>    本文压缩**智能体间的工具调用消息**，并专门研究**定长截断**这一族。
>
> ⚠️ **一条必须守住的边界**：本文 §6.4 证明的是"**按字符预算截断**的摘要要么坏、要么不便宜"，
> **这不适用于学习到的语义摘要**。EcoAgent 的 Pre-understanding Module 属于后者，
> 因此**不得把 §6.4 外推为"摘要无用"**。正文已加注。
