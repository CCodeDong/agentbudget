# L9 数据持久化

**日期**：2026-10-24
**设备**：MateBook Pro（HAD-W32）/ 2in1 / API 23

## 一、补上的是什么缺口

核心库里早就有 `DocStore.save()/load()`，**但页面从来没调用过**。

后果是：应用一关资料全没；下次打开因为库是空的，`seedDemo()` 又塞回示例 ——
**看起来像正常，其实每次都在重新开始。**

一个"资料库"关掉就忘事，不是小瑕疵，是功能不成立。

## 二、实现

`lib/librarystorage.ets`：读写应用沙箱的 `filesDir/library.json`

- **每次改动立即落盘**，不是退出时保存。
  理由：HarmonyOS 的 UIAbility 后台时可能被系统直接回收，`onDestroy` 不保证被调用。
- **先删再建**，避免新内容比旧内容短时尾部残留。
- 自己写 UTF-8 解码，不依赖 TextDecoder。
- `finally` 里关 fd。

### 一个刻意的区分

`restoreOrSeed()` 区分两种"空"：

| 情况 | 处理 |
|---|---|
| **从没有存档**（首次启动） | 放示例，让用户知道能干什么 |
| **有存档但里面没文档**（用户删光了） | **不放示例**，尊重用户的删除 |

把两者混为一谈，用户体验就是"删了又回来"。

## 三、真机验证

| 步骤 | 结果 |
|---|---|
| 首次启动 | 放入示例并落盘，`library.json` 442 B |
| 强杀进程 | 进程数 0 |
| 重启 | 显示「已恢复 1 份资料」，**只有 1 份**（不是重新种示例） |
| 用户手动导入一份 | 落盘成功（存档里能搜到用户内容标记） |
| 再次强杀 + 重启 | 显示「已恢复 **2** 份资料」，示例与用户资料都在 |

2. `02-用户资料也活过重启.jpeg` —— 2 份，用户加的"未命名资料 20 字"仍在
