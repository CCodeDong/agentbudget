# 移动应用演示：预期界面状态清单

> **用途**：移动端演示需要真机，作者当前无设备。本清单把每个镜头应有的**界面输出**写成可逐项核对的表格，
> 使录制时不必依赖记忆判断"是否对"，也让**录制失败（与实际不符）能被立即发现**。
>
> **为什么不是"录制脚本"而是"预期状态清单"**：脚本会随代码漂移
> （本项目已因此吃过一次亏——命令行里的 `--ks=-1` 在参数化后不再表示原策略）。
> 清单核对的是**代码实际应该产出什么**，而不是**上次录制时看到了什么**。

## 二、逐镜头预期状态

初始状态：网络 = **弱网**，局域网开关 = **开**，预算滑块 = **85%**，
任务 = `search my files for the quarterly report`。

| # | 操作 | 预期界面输出 | 为什么这一格重要 |
|---|---|---|---|
| 1 | 启动应用 | 显示编排控制台：任务输入框 / 网络档位 / 局域网开关 / 预算滑块 / top-k 按钮 | 镜头 1 只需证明应用可运行 |
| 2 | 默认状态（弱网 + LAN + **85%**）点"运行一步" | 执行位置 **edge**；消息形式 **structured**；工具策略 **two-stage-top3**；验证 **通过** | 基线：弱网 + 局域网可达时应保住边缘 |
| 3 | 关闭"局域网"开关 → 运行 | 执行位置变为 **on-device**；其余同上 | 证明 edge 与广域网解耦：无 LAN 才退到设备 |
| 4 | 恢复 LAN；**预算拉到 75%**；网络切 **WiFi** → 运行 | 执行位置变为 **cloud** | 三层各自显现。**必须先降预算**——云的条件含 `util < 0.8`，85% 时 WiFi 仍给 edge |
| 5 | 网络切回弱网；预算拉到 **45%** → 运行 | 消息形式 **summary**；工具策略 **eager**；验证器 **FAIL** | **核心镜头**：截断破坏参数 → 现场复现"省与完整互斥" |
| 6 | 点"A2A 试运行" | 显示 A2A 消息形式与**线缆字节数** | 方法在协议层的落点：形式决定 `Part` 通道 |
| 7 | 预算拉回 **85%** → 运行 | 消息形式 **structured**；工具策略 **two-stage-top3**；验证 **通过** | 与方法描述一致 |

> **上表每一格的 route / msgForm / strategy 都经 `agentbudget4cj` 实际运行核对过**，
> 不是凭记忆写的。核对命令见本节末。
>
> **两处曾写错并已修正**（这张清单在写完后的自检中抓到了它们）：
> 1. 镜头 4 原写"WiFi → cloud"。实际在 85% 预算下 WiFi 也走 **edge**，
>    因为云的条件含 `util < 0.8`。**必须先降预算才能看到 cloud。**
> 2. 镜头 5 原未写明工具策略。实际 util=45% 时 `util < 0.5` 且 eager 仍然可行，
>    因此走**eager 短路**，策略是 `eager` 而非 `two-stage-top3`。

### 核对命令（可复现上表）

```powershell
# tier rtt metered lan spent cap cloudLeft mode topK query
0.8 weak  1500 1 1 6800 8000 10 budget -50 search my files for the quarterly report
0.8 weak  1500 1 0 6800 8000 10 budget -50 search my files for the quarterly report
0.8 wifi  20   0 1 6000 8000 10 budget -50 search my files for the quarterly report
0.8 weak  1500 1 1 3600 8000 10 budget -50 search my files for the quarterly report
```

依次应输出 `edge` / `on-device` / `cloud` / `summary+eager`。

### 镜头 5 的讲解要点

`summary` 在此**确实更便宜**，但验证器**拿不到参数**。
把预算调大到能容纳负载时，它的成本又追平结构化编码——
**不存在既完整又明显更便宜的预算**。

> ⚠️ **讲解时不要说"摘要无用"**。本项目的结论只针对**按字符预算的定长截断**，
> 不适用于学习到的语义摘要（如 EcoAgent 的 Pre-understanding Module）。详见论文 §6.4 的边界声明。

### 镜头 6 的讲解要点

消息形式不是"建议"，而是**决定用哪个 `Part` 通道**：
`structured` 走 `Part.data`（带 `mediaType`），其余走 `Part.text`。
由于 A2A 传输层只在真机上存在，该按钮走 `dryRun()`——**完整的调度与编码路径，不含传输**。

## 三、录制后应能回答的问题

若以下任一问题答不上来，说明录制不完整：

1. 弱网下应用把这一步放在哪一层？为什么不是设备？（→ edge；LAN 仍可达）
2. 什么条件下消息形式会变成 `summary`？后果是什么？（→ 预算 30–60%；验证器失败）
3. A2A 的 `structured` 形式用哪个通道承载负载？（→ `Part.data`）
4. 演示中的失败是**设计出来的可复现失败**，还是应用有缺陷？（→ 设计；用于复现研究结论）
