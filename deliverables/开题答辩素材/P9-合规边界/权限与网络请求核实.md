# 权限与网络请求核实（P9 素材）

> 把 P9 的"单机应用免备案"从**主张**变成**有证据的主张**。

---

## 一、我们的应用实际申请了哪些权限

来自 `entry/src/main/module.json5`：

```json5
"requestPermissions": [
  {
    "name": "ohos.permission.GET_NETWORK_INFO",
    "reason": "$string:reason_network_info",
    "usedScene": { "abilities": ["EntryAbility"], "when": "inuse" }
  }
]
```

**全部权限只有一个**：`GET_NETWORK_INFO`（**读取**网络状态，例如判断当前是 WiFi 还是移动网络）。

**没有申请 `ohos.permission.INTERNET`。**

---

## 二、代码里是否真的不发网络请求

对全部 ArkTS 源码做模式检索（`http.createHttp` / `request(` / `fetch(` / `WebSocket` / `rcp.`）：

**结果：无任何匹配。**

网络相关代码只做了一件事——**读取**当前网络档位：

```typescript
import { connection } from '@kit.NetworkKit';

const net = connection.getDefaultNetSync();
const caps = connection.getNetCapabilitiesSync(net);
```

`connection` 模块的 `getDefaultNetSync` / `getNetCapabilitiesSync` 是**只读查询**，
不具备发起请求的能力。

---

## 三、结论（可直接用于 P9/P13）

| 主张 | 证据 |
|---|---|
| 不申请 `INTERNET` 权限 | ✅ `module.json5` 只声明了 `GET_NETWORK_INFO` |
| 代码不发起网络请求 | ✅ 全量源码检索无匹配 |
| 无服务端、不上传数据 | ✅ 没有可上传的通道 |

> **"资料不出设备"因此是可验证的结论，而不是宣传语。**

**验证方法本身也可以写进 PPT**（P13 主张"隐私可验证"）：

1. **静态权限分析**：读 `module.json5` 的 `requestPermissions`
2. **代码级检索**：全量搜索网络请求 API
3. **断网运行**：飞行模式下跑通全流程
4. **抓包**：确认无出站连接

---

## 四、⚠️ 关键提醒：不要照搬到「离线资料库」

**我们的应用申请了 `GET_NETWORK_INFO`，原因是我们需要它。**

我们的调度器要判断"当前网络档位"来决定执行位置（本地/边缘/云）——
**这是网络感知调度器的必需输入**。

**但「离线资料库」不需要网络感知**，因此可以：

| | 我们的调度器 | 「离线资料库」 |
|---|---|---|
| 需要网络状态吗 | **需要**（决定在哪执行） | **不需要** |
| 可以申请的权限数 | 1 个（`GET_NETWORK_INFO`） | **0 个** |

**「离线资料库」应当做到零网络相关权限**——那样 P9 的"勾选单机应用 → 免备案"
才是**毫无争议**的。

> **这是一个刻意设计上的差异，不要把我们的权限清单直接搬过去。**
> 反过来说：如果「离线资料库」也申请了 `GET_NETWORK_INFO`，
> 审核方可能会追问"你读网络状态做什么"，反而增加解释成本。
