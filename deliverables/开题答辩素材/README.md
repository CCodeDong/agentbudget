## 各目录内容与用法

### P6-平台能力

**用途**：支撑 P6 的能力表，且**证据强度高于"查文档"**——它是从**本地 SDK 的元数据文件**现场提取的，可复现。

| 文件 | 内容 |
|---|---|
| `capability-matrix.json` | 11 项 AI 能力在 phone / tablet / 2in1 三种形态下的可用性 |
| `平台能力对照.md` | 说明文档（含提取方法与结论） |

**核心结论**（可直接写进 PPT）：

| 能力 | phone | tablet | 2in1 |
|---|---|---|---|
| `AI.CANN.LLMEngine` | — | — | **有** |
| `DataAugmentation.Retrieval` | **有** | **有** | **有** |
| `AI.OCR.TextRecognition` | **有** | **有** | **有** |
| `AI.Agent.AgentKit` | **有** | **有** | — |

> **手机确实不能自部署大模型，但检索/OCR/语音都开放。**
> 这**直接支撑** P6 的"端侧 AI 能力已经就位"与"手机无法运行本地大模型"两条论断。

### P9-合规边界

**用途**：把 P9 的"单机应用免备案"从**主张**变成**有证据的主张**。

| 文件 | 内容 |
|---|---|
| `权限与网络请求核实.md` | 权限清单 + 代码级网络请求检查结果 |

**核心证据**：
- 应用的**全部权限只有一个**：`ohos.permission.GET_NETWORK_INFO`（读取网络状态）
- **代码中不存在任何网络请求调用**（已用脚本全量检索 ArkTS 源码）
- 没有服务端，不上传任何数据

> ⚠️ **注意**：我们的应用申请了 `GET_NETWORK_INFO`。
> 如果「离线资料库」要主张"零网络权限"，**这一点要刻意不同**——
> 那个应用不需要判断网络档位，可以完全不申请任何网络相关权限。
> **这是两个应用，不要把我们的权限清单直接照搬过去。**

### P11-模拟器与设备 ⭐ 最有价值的一批素材

**用途**：P11 说"鸿蒙模拟器不支持任何 AI 能力"——**我们有硬证据**。

| 文件 | 内容 |
|---|---|
| `模拟器崩溃实证.md` | **崩溃日志原文 + 因果分析** |
| `设备实测记录.md` | 我们实测过的两台设备与结论 |

**这是整包里最有说服力的一份**，因为它不是引用官方文档，而是**我们自己撞上去、并把原因定位到了具体一行**：

```
LastFatalMessage: [LoadJSPandaFile] load hsp failed,
  hsp name: com.huawei.hmsapp.hiai.hsp/agentKitHsp,
  errorMsg: Get shared HspPath failed
Reason: Signal:SIGABRT ... SourceTextModule::Instantiate
```

**含义**：HMS 能力（Kit）在**模块加载期**解析，设备上没有对应 HSP 时
**应用在任何代码执行前就崩溃**——不是"功能不可用"，是**整个应用起不来**。

**这给 P11 增加一条它现在没有的、更硬的论据**：

> 模拟器不仅"AI 能力不可用"，而且**如果应用静态导入了这些 Kit，应用会直接崩溃**。
> 因此"把 AI 能力抽成可降级模块"不是优化，是**必需**。

### P15-预算感知调度 ⭐ 核心

**用途**：这是**创新点一的完整实现与验证**，也是整个素材包里与研究最直接对应的部分。

| 文件 | 内容 | 对应 PPT 的哪一句 |
|---|---|---|
| `fig9_score_driven_k.png` | 得分驱动的自适应 top-k | P15「检索…**由查询复杂度与结果分布驱动**」 |
| `fig8_adaptive_k.png` | 预算驱动的自适应 top-k（**被严格支配**） | 反例：说明"用错信号的后果" |
| `fig1_pareto_k.png` | 免费压缩区间 | "有限算力下做到够用"的定量答案 |
| `fig5_retrieval_fix.png` | 代价 100% 来自检索漏选 | 说明代价来源，指导优化方向 |
| `实验数据摘要.csv` | 11 个套件 / 3,960 次运行的汇总 | 支撑"可测量、可复现" |

**可直接写进 P15 的核心论点**：

> 我们不只是**主张**"不同环节需要不同信号"，而是**用一对正负实验证明了它**：
> - 用**错误的信号**（剩余预算）去驱动检索深度 → 该策略**每一个工作点都被某个固定策略严格支配**
> - 用**正确的信号**（检索得分分布）→ 该策略**支配每一个固定策略，且自身不被支配**

**为什么这对 PPT 特别有价值**：P15 目前是**主张**（"我们用不同的信号"），
而素材提供的是**证据**（"我们试过用错信号，它被支配；换对信号后它支配了所有固定策略"）。

## 实际踩到的坑（可用于 P12 风险表）

这些是**真实发生过的**，比预想的风险更有说服力：

| 坑 | 后果 | 应对 |
|---|---|---|
| **HMS Kit 缺失导致应用崩溃** | 应用**完全无法启动**（不是功能降级） | 把 Kit 依赖抽成可降级模块，主路径不静态导入 |
| 模拟器**不含 HMS Core** | 任何调用 Kit 的功能都不可用 | 必须真机或云真机 |
| **调试证书 ≠ 发布证书** | 产物无法上架 | 第 1 周就申请 AGC 发布证书 |
| 设备 API 23 < SDK API 26 | 高版本 API 不可用 | 编译前确认目标设备 API |
| 构建路径含非 ASCII 字符 | `cjpm` 与 `hvigor` 均失败 | 工程路径改纯 ASCII |

## 使用时的三条提醒

1. **不要把两个项目混为一谈**。开题的是「离线资料库」，已完成的是「预算调度器」。
   正确关系是：**前者借用后者的调度思路，后者是前者的技术验证**。

2. **标注证据来源与强度**。我们的图来自模拟推理端点的实验，截图来自**模拟器**。
   P16 主张"真机实测"——**这两者不能混用**。

3. **PPT 上的数字要能追溯**。素材包里每个数字都对应一份可复现的原始数据，
   这正是 P16 想要展示的"可复现"。
