# 平台能力对照：手机 / 平板 / 2in1（P6 素材）

> **证据强度**：从**本地 SDK 的元数据文件**现场提取，**可复现**——
> 不是从文档抄的，也不是凭印象。

---

## 一、数据从哪来

DevEco Studio 的 SDK 里有**按设备形态分文件**的能力清单：

```
D:\develop\DevEco Studio\sdk\default\hms\ets\api\device-define\
├── phone-hmos.json      127 条 SystemCapability
├── tablet-hmos.json     124 条
└── 2in1-hmos.json       115 条
```

**每个文件列出该形态实际公开的系统能力。** 查一个能力在不在里面，就知道该形态能不能用。

`capability-matrix.json` 是从这三个文件现场提取的结果，可重新生成验证。

## 三、两条结论（对应 P6 的两句论断）

### 结论 1：手机**不能**自部署大模型 ✓

`AI.CANN.LLMEngine` 与 `DataAugmentation.LocalChatModel`
**只出现在 2in1 形态**，手机与平板都没有。

> **这直接支撑 P6 的**："手机无法运行本地大模型"
> **也直接支撑 P9 的**："不能生成式 → 不触发生成式 AI 备案"

### 结论 2：端侧 AI 能力**已经就位** ✓

P6 列的四项能力，我们**逐项核实了在 phone 形态的存在性**：

| P6 列的能力 | P6 写的 | 我们的核实 |
|---|---|:---:|
| 文字识别 OCR | ✅ API 10+ | ✅ **phone 可用** |
| 语音识别 / 合成 | ✅ API 12+ | ✅ **phone 可用** |
| 端侧检索（召回） | ✅ API 20+ | ✅ **phone 可用** |
| 意图框架 | ✅ API 12+ | ⚠️ 见下方说明 |

## 四、两处需要修正或确认的地方

### ⚠️ 1. P6 表格里的"意图框架 Intents Kit"

我们在 phone 形态的能力清单里**没有找到** `AI.Intents.IntentsKit`。

但**找到了** `AI.InsightIntent`（对应"意图框架"的另一种命名）。
**建议**：P6 表格里的 Kit 名称在答辩前用官方文档核对一遍，
或用 `AI.InsightIntent` 这个实际出现在能力清单里的名字。

### ⚠️ 2. P11 提到的 AGC 云调试 —— 我们没有验证过

P11 写"AGC 云调试每日 360 分钟免费""需上传 release 签名包"。
**这些我们没有实测**，属于引用信息，**建议标注来源**。

## 五、对「离线资料库」项目的直接启示

| 启示 | 依据 |
|---|---|
| **不要指望端侧大模型** | `LLMEngine` 手机不可用——这支撑了"检索式而非生成式"的路线 |
| **OCR 与检索是可行的** | 两者都在 phone 形态公开 |
| **能力可用 ≠ 应用能用** | 见 [`../P11-模拟器与设备/模拟器崩溃实证.md`](../P11-模拟器与设备/模拟器崩溃实证.md)——**缺少 HSP 时应用会崩溃** |
| **目标设备 API 要确认** | 我们的真机是 API 23，而 SDK 是 API 26（只有一个版本，无法降级） |

## 六、复现方法

```python
from pathlib import Path
d = Path(r"D:\develop\DevEco Studio\sdk\default\hms\ets\api\device-define")
forms = {"phone": "phone-hmos.json", "tablet": "tablet-hmos.json", "2in1": "2in1-hmos.json"}
text = {k: (d / v).read_text(encoding="utf-8") for k, v in forms.items()}
for cap in ["AI.CANN.LLMEngine", "DataAugmentation.Retrieval", "AI.OCR.TextRecognition"]:
    print(cap, {k: ("有" if cap in t else "-") for k, t in text.items()})
```
