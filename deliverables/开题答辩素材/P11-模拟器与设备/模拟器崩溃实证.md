> 而是我们自己撞上去、并把原因定位到了**具体一行日志**。

## 一、硬证据：应用在模拟器上直接崩溃

### 崩溃日志原文

从设备取回的 `cppcrash` 报告（`/data/log/faultlog/faultlogger/`）：

```
Generated by HiviewDFX@OpenHarmony
Device info:emulator
Build info:emulator 7.0.0.107(SP8DEVC00E999R4P11)
Module name:com.xjtu.agentbudget
Reason:Signal:SIGABRT(SI_TKILL)@0x... from:8039:20020063

LastFatalMessage:[default] [LoadJSPandaFile] load hsp failed,
  hsp name:com.huawei.hmsapp.hiai.hsp/agentKitHsp,
  errorMsg:Get shared HspPath failed, please check the module is correct

Fault thread info:
#02 ... libark_jsruntime.so
#08 ... panda::ecmascript::SourceTextModule::Instantiate(...)
```

### 关键信息逐条解读

| 日志片段 | 含义 |
|---|---|
| `load hsp failed` | 共享库（HSP）加载失败 |
| `hsp name: com.huawei.hmsapp.hiai.hsp/agentKitHsp` | **HMS 的 AgentKit 共享库**——模拟器镜像里没有 |
| `SourceTextModule::Instantiate` | 崩溃发生在**模块实例化阶段** |
| `SIGABRT` | 进程被**强制终止**，不是抛异常 |

### 结论（可直接写进 PPT）

> **HMS Kit 是在模块加载期解析的。设备上没有对应 HSP 时，应用会在
> 任何应用代码执行之前就崩溃——不是"功能不可用"，而是"整个应用起不来"。**

## 二、这件事对 P11 的三点价值

### 1. 它把"模拟器不可用"从断言变成了证据

P11 现在的说法是"鸿蒙模拟器不支持任何 AI 能力（官方明文）"。
**引用官方文档是一回事，自己撞上并定位到具体一行是另一回事。**

### 2. 它揭示了一个 P11 目前没提到的、更严重的问题

模拟器不只是"AI 能力不可用"，而是——

> **如果应用静态导入了这些 Kit，应用会直接崩溃。**

这带来一个**设计上的强制要求**：

> **AI 能力必须抽成可降级模块，主路径不能静态导入 Kit。**
> 否则应用在缺少 Kit 的设备上根本无法启动。

**这不是优化建议，是必需。** 对「离线资料库」项目特别重要——
它要用 OCR（Vision Kit），如果直接 `import` 就会重蹈覆辙。

### 3. 它给出了一个可复现的排查方法

遇到应用"启动即崩溃"时，正确的排查路径是：

```powershell
# 1. 取回崩溃日志
hdc file recv /data/log/faultlog/faultlogger/<最新cppcrash>.log ./crashlog

# 2. 看 LastFatalMessage 那一行 —— 它通常直接指出原因
```

## 三、我们实测过的设备

| 设备 | 形态 | 系统 | API | 结果 |
|---|---|---|---|---|
| **MateBook Pro**（HAD-W32） | 2in1 | OpenHarmony-6.1.0.115 | **23** | 可连接；**无 A2A/Agent 相关包** |
| **Pura 90 Pro**（模拟器） | **phone** | emulator 7.0.0.107 | **26** | 可运行；**无任何 HMS 包** |

### 实测得到的两个事实

**事实 1：模拟器镜像不含 HMS Core**

在模拟器上执行 `bm dump -a` 查已安装包，**没有任何 `com.huawei.hms.*` 或 Agent 相关包**。
（对照：真机 MateBook 上有 `com.huawei.hms.huaweiid`、`com.huawei.hms.payment` 等多个 HMS 包。）

**事实 2：设备 API 版本可能低于 SDK**

电脑上装的 SDK 是 **API 26**（HarmonyOS 26.0.0），
而 MateBook 真机是 **API 23**。**电脑上只有一个 SDK 版本，无法降级编译。**

> ⚠️ 这对「离线资料库」是**实际风险**：
> 如果目标设备是旧版 HarmonyOS，而工具链只有新版 SDK，
> **高版本 API 在设备上会失效**。P11 应该把"确认目标设备 API"列进 W1。

## 四、连接方式（附带的一条实用经验）

真机可以通过**无线调试**连接，不需要 USB：

```powershell
hdc tconn <设备上显示的IP>:<端口>
```

对「离线资料库」的意义：**取证与测试不一定要受 USB 线限制**。

> 注意：hdc 3.2.0f **没有 `pair` 命令**（不同于 Android 的 adb），
> 所以必须在**设备端**先打开"无线调试"读出 IP 与端口。

## 五、诚实说明

- 崩溃日志来自我们自己的应用（`com.xjtu.agentbudget`），**不是「离线资料库」的应用**
- 但它证明的是**通用的机制**：HMS Kit 缺失 → 模块加载期崩溃
- 「离线资料库」若使用 Vision Kit（OCR），**会面临同样的问题**
- 我们**没有在真机上成功运行过**依赖 HMS Kit 的功能——两台可用设备都不具备条件
