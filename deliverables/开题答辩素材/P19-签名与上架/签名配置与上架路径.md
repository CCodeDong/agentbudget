## 一、我们当前的签名状态（反面教材）

`app/harmony/build-profile.json5`：

```json5
"signingConfigs": [
  {
    "name": "default",
    "type": "HarmonyOS",
    "material": {
      "certpath": "C:\\Users\\86178\\.ohos\\config\\default_harmony_*.cer",
      "keyAlias": "debugKey",          // ← 调试密钥
      "profile":  "C:\\Users\\86178\\.ohos\\config\\default_harmony_*.p7b",
      "storeFile":"C:\\Users\\86178\\.ohos\\config\\default_harmony_*.p12"
    }
  }
]
```

**这是 DevEco 自动生成的调试签名**，不能用于上架。

| 字段 | 当前值 | 上架要求 |
|---|---|---|
| `keyAlias` | **`debugKey`** | 发布密钥 |
| 证书 | `default_harmony_*.cer`（自动生成） | **AGC 申请的发布证书** |
| Profile | `default_harmony_*.p7b`（调试用） | **AGC 的发布 Profile** |
| 存放位置 | `C:\Users\<用户>\.ohos\config\` | 自定，但要妥善保管 |

> 💡 **一个容易困惑的点**：DevEco 26 把签名材料放在**用户目录** `~/.ohos/config/`，
> **不在工程目录里**。所以"配好了自动签名但工程里找不到 `.p12`"是正常的。

## 二、发布签名要准备的三样东西

| 需要 | 从哪来 | 耗时 |
|---|---|---|
| **发布密钥库 `.p12`** | **你自己生成**（DevEco 或命令行） | 立刻 |
| **发布证书 `.cer`** | AGC → 证书管理 → 生成 CSR → 上传 → 下载 | 1–2 天 |
| **发布 Profile `.p7b`** | AGC → Profile 管理 → 绑定包名 → 下载 | 同上 |

### 操作顺序

1. **AppGallery Connect → 我的应用 → 新建应用**
   - **包名一旦确定不能改**（我们用的是 `com.xjtu.agentbudget`）
2. **证书、Profile 管理 → 证书 → 新增**
   - 生成 CSR → 上传 → 下载 `.cer`
3. **Profile → 新增**
   - 绑定包名 → **勾选需要的权限**（P19 提到要勾 Vision Kit）→ 下载 `.p7b`
4. 把三样东西配进 `build-profile.json5`（或 DevEco 的 Signing Configs 界面）

> ⚠️ **`.p12` 丢失 = 应用永远无法发布更新。** 必须备份，且**绝不能提交到 git**
> （我们的 `.gitignore` 已排除 `*.p12` / `*.p7b` / `*.cer`）。

## 三、构建产物：`.hap` 与 `.app` 的区别

| 命令 | 产物 | 用途 |
|---|---|---|
| `hvigorw assembleHap` | `.hap` | 单模块包，用于**调试安装** |
| `hvigorw assembleApp` | **`.app`** | **App Pack，用于上架** |

**我们实测过**：`assembleApp` 能成功执行（含 `SignApp` 任务）。

```
$ hvigorw assembleApp
  > hvigor Finished ::SignHap...
  > hvigor Finished ::SignPackagesFromApp...
  > hvigor Finished ::SignApp...
  > hvigor BUILD SUCCESSFUL

产出: build/outputs/default/harmony-default-signed.app   134,172 B
```

> ⚠️ **一个未查清的差异**：`assembleHap` 与 `assembleApp` 产出的 HAP 大小不同
> （251,360 B vs 184,116 B）。**原因我们尚未确证**。
> 上架前应查清该提交哪个。

## 四、对 P19 的直接建议

P19/W1 的计划是对的（"第 1 周申请 release 签名"），**建议补充两条**：

### 补充 1：明确"包名在建应用时就定，之后不可改"

P19/W1 已写"确定 Bundle Name（上架后不可改）"——**这一点值得加粗强调**。
包名同时出现在 AGC 应用、Profile 绑定、`build-profile.json5` 三处，**必须一致**。

### 补充 2：`.p12` 的备份策略要写进计划

**丢了就无法更新应用**，且它是**不可恢复**的。
建议：放进密码管理器 + 离线备份，**且永远不进 git**。
