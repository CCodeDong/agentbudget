## 2. 两项产出共享同一个研究点

这是本项目最重要的结构性设计：**两门课不是两个无关的作业，而是同一项研究的两侧。**

```
        仓颉语言课程                        移动应用开发课程
   ┌──────────────────────┐          ┌──────────────────────┐
   │ agentbudget4cj       │          │ HarmonyOS 应用       │
   │ 决策层（被测量对象）  │◀─────────│ 编排层（承载与演示） │
   │ 预算/工具/编解码/路由 │  决策    │ A2A / 三智能体 / 工具 │
   └──────────┬───────────┘          └──────────┬───────────┘
              └────────────┬────────────────────┘
                           ▼
              ┌────────────────────────────┐
              │ 论文：端侧多智能体预算调度  │
              │ 6 个实验，3960 次运行       │
              └────────────────────────────┘
```

**报告中的每一个数字都可追溯到一次记录在案的运行**（`experiments/results*/`）
或一份构建日志。内容生成脚本从这些数据文件直接读取，因此**文档不会与证据悄悄脱节**。

### 3.1 仓颉语言课程（无需真机，PC 录屏即可）

| 镜头 | 内容 | 命令 / 操作 |

| 1 | 代码结构总览 | 打开 `projects/agentbudget4cj/src/`，展示 8 个源文件 |

| 3 | 覆盖率报告 | `... cover` 后打开 `_out/coverage_html/index.html` |
| 4 | **基准测试** | `... bench` → 展示 Median/Err%/Mean 表格 |
| 5 | **决策引擎实际运行** | `python tools\demo_run.py --show`（见下） |
| 6 | 优化前后对比 | 展示 `docs/04` 中的 8.237 ms → 4.743 ms |

**镜头 5 已脚本化并有实录**：[仓颉演示实录.md](演示素材/仓颉演示实录.md)
由 `tools/demo_run.py` **实际执行并捕获输出**生成，含 5 段：

1. 三层放置（wifi→cloud / 弱网+LAN→edge / 弱网无 LAN→device）
2. 自适应 top-k：对查询歧义敏感、对预算不敏感
3. 三种选择器对比：得分驱动 / 预算驱动 / 固定 k
4. 消息表示：natural 28 token → summary 18（截断）→ structured 17（无损）
5. 工具池 5 vs 15：可复现性为何是硬要求

> **为什么用脚本而不是手敲命令**：手抄的演示命令会与代码漂移。
> 本项目已因此吃过一次亏（命令里的 `--ks=-1` 在参数化后不再表示产生数据时的策略），
> 所以演示输出与实际运行必须是同一个来源。

### 3.2 移动应用开发课程（需真机）

| 镜头 | 内容 |
|---|---|
| 1 | 应用启动，展示编排控制台界面 |
| 2 | 默认状态（弱网 + 局域网可达 + 预算 85%）→ 运行一步 → 显示 `edge` / `structured` / 验证通过 |
| 3 | 关闭局域网开关 → 运行 → 落点变为 `on-device` |
| 4 | 网络切到 WiFi → 运行 → 落点变为 `cloud` |
| 5 | **关键镜头**：预算滑块拉到 45% → 运行 → 消息形式变为 `summary` → **验证器报告 FAIL** |
| 6 | **A2A 试运行**：点击后显示经真实 `@hms.ai.A2A` 编码路径的消息形式与线缆字节数 |
| 7 | 预算拉到 85% → 运行 → `structured` → 验证通过，且上下文 token 显著下降 |

**镜头 5 是整个演示的核心**：它把「截断式摘要的省与完整互斥」这一结论做成了现场可复现的失败。
讲解时要点明：预算 45% 时 `summary` 确实更便宜，但**验证器拿不到参数**；
而把预算调大到能容纳负载时，它的成本又追平结构化编码——
**不存在既完整又明显更便宜的预算**。

**镜头 6 是本项目方法在协议层的落点**：消息形式不是"建议"，
而是决定用哪个 `Part` 通道（`structured` 走 `Part.data`，其余走 `Part.text`）。
由于 A2A 传输层只在真机上存在，该按钮走 `dryRun()`——完整的调度与编码路径，不含传输。

> 拍摄前请先完成真机调试链路（第 4 节）。

实验当前使用模拟推理端点，其数值属**管线验证**。
