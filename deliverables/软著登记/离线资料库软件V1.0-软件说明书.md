## 一、软件概述

### 1.1 软件定位

**离线资料库软件**是一款运行于 HarmonyOS 设备的个人资料检索工具。用户把课堂讲义、书页照片、笔记片段导入后，可以用自然语言描述记得的内容，软件在本机完成检索并**返回原文片段与高亮位置**。

**核心特征**：全程离线，不发起任何网络请求，资料不出设备。

### 1.2 解决的问题

纸质与碎片资料"存得下、找不回"：

| 场景 | 现状 |
|---|---|
| 课堂板书、讲义、PPT 拍成照片 | 躺在相册里，只能靠翻，无法按内容搜索 |
| 书上的重点、资料截图 | 存进备忘录后检索不到原文 |
| 图书馆、地铁、教室等弱网/无网环境 | 云端笔记类应用直接不可用 |
| 学习资料、证件、内部讲义 | 上传云端有隐私顾虑 |

本软件针对的正是这四类场景：**要找得到、不用联网、不用上传**。

### 1.3 与同类方案的差异

| 维度 | 系统备忘录/图库 | 云端笔记 | 扫描类应用 | **本软件** |
|---|:---:|:---:|:---:|:---:|
| 全程离线 | 是 | 否 | 部分 | **是** |
| 数据不出设备 | 是 | 否 | 部分 | **是** |
| 可按内容检索原文 | 部分 | 是 | 否 | **是** |
| 跨来源统一建库 | 否 | 是 | 否 | **是** |
| 可追溯出处与高亮 | 否 | 部分 | 否 | **是** |

## 三、软件架构

### 3.1 模块划分

软件由七个核心模块与一个界面层构成：

| 模块 | 职责 |
|---|---|
| `types` | 数据结构定义（文档、片段、命中、预算） |
| `tokenize` | 中英文切词 |
| `index` | 倒排索引构建、BM25 打分、文本分块、高亮定位 |
| `search` | 检索入口、自适应结果数量决策、资源预算决策 |
| `store` | 文档存储与 JSON 持久化 |
| `ocr` | 光学字符识别抽象层与识别质量判定 |
| `pipeline` | 流水线编排（导入 → 分块 → 建索引 → 检索） |
| `pages/Index` | 用户界面 |

### 3.2 数据流

```
导入资料 ──> 切词 ──> 倒排索引 ──┐
                                  │
用户查询 ──> 切词 ──> BM25 打分 ──┴──> 候选排序 ──> 决定返回条数 ──> 高亮呈现
```

## 四、功能说明

### 4.1 资料导入

软件支持三种导入方式：

| 方式 | 说明 |
|---|---|
| 粘贴文本 | 用户直接粘贴或输入内容，无需 OCR |
| 拍照识别 | 调用设备 OCR 能力识别图片文字（需设备支持） |
| 文件导入 | 从本地文件选择导入（后续版本） |

**导入流程**：

1. 用户填写标题（可留空，默认"未命名资料"）
2. 输入或识别文本内容
3. 软件按内容长度**自适应选择分块大小**
4. 文本被切成可检索片段并加入索引
5. 界面显示入库结果与片段数量

### 4.2 资料检索

**操作**：在搜索框输入关键词或描述，点"搜索"。

**检索流程**：

1. 对查询串做切词
2. 在倒排索引中定位候选片段
3. 用 BM25 算法对候选打分并排序
4. **根据得分分布决定返回几条**（详见 5.2）
5. 在结果中高亮显示命中词

**结果呈现**：每条结果显示来源资料标题、相关度得分、文本片段，命中词以红色加粗高亮。

### 4.3 检索决策说明

软件在结果上方显示一行决策说明：

```
返回 N 条 · 来源 score-gap · 限制方 information
候选 M 条 · 资源约束：<理由>
```

**这行说明的含义**：告诉用户本次为什么只返回这几条——是内容层面判断"只有这几条相关"，还是资源层面"再多取就超出时间/内存预算"。

### 4.4 资料管理

| 功能 | 说明 |
|---|---|
| 资料列表 | 显示全部资料标题、来源类型、字符数 |
| 删除 | 删除资料并同步更新索引 |
| 统计 | 显示资料份数、片段数、待整理片段数 |
| 持久化 | 全部资料可序列化为 JSON 保存，启动时恢复 |

### 4.5 自测功能

软件内置一个自测页面，运行 14 项断言检查核心功能是否正常，结果以列表形式显示（通过/未通过）。

**用途**：在设备上验证软件核心逻辑的正确性，便于排查环境问题。

## 五、技术特点

### 5.1 不依赖词典的中文切词

手机端没有可用的中文分词词典，也无需为此引入数十兆的词表。本软件采用**单字 + 相邻二元组**的方式切词：

```
"离线资料库" → 离 / 线 / 资 / 料 / 库
               离线 / 线资 / 资料 / 料库
```

**效果**：不做分词也能达到可用的召回率，代价是索引词项数约为文本字数的两倍。
英文与数字按非字母数字切分并统一转小写。

### 5.2 由得分分布决定返回条数

**这是本软件与同类工具最主要的区别。**

多数检索工具返回固定条数（如前 3 条、前 10 条）。固定条数的问题在于：
查询明确时返回过多无关内容，查询模糊时返回不足。

本软件的做法是**观察候选的得分分布**：

1. 计算相邻候选得分的**相对落差**
2. 找到最大落差所在位置
3. 若该落差超过 5%，说明此处存在明显断层 —— **断层之前的是真正相关的**
4. 若分布平坦（无可信断层），说明无法区分相关程度，取上界
5. 结果数量约束在用户设定的上下界之间

**实测效果**（150 条已知答案查询，真实语料 2,295 个片段）：

| 策略 | 召回率 | 精确率 | 平均返回条数 |
|---|---|---|---|
| 固定 3 条 | 100% | 59.8% | 3.0 |
| **本软件的得分分布策略** | **100%** | **89.4%** | **1.8** |

**即：同样的召回率，精确率高约 30 个百分点，平均少返回 40% 的内容。**

### 5.3 资源预算独立决策

软件区分两类问题：

| 问题 | 由什么决定 |
|---|---|
| **该取几条**（信息层面） | 候选的得分分布 |
| **还取得起几条**（资源层面） | 可用时间、可用内存、当前电量 |

两者取较小值，并在界面上显示是哪个在限制。**电量低于 15% 时主动降级**，减少返回条数以降低耗电。

**设计意图**：把"内容相关性"和"资源可用性"分开判断，而不是用一个"剩余额度"混为一谈。

### 5.4 分块随内容长度自适应

| 文本长度 | 分块大小 | 重叠 |
|---|---|---|
| ≤ 1,000 字 | 整篇一块 | 无 |
| 1,000 – 20,000 字 | 240 字 | 40 字 |
| > 20,000 字 | 400 字 | 60 字 |

相邻块保留重叠，避免关键词被切在边界上导致漏检。

### 5.5 能力缺失时的降级设计

光学字符识别被设计为**可替换接口**而非硬依赖。

- 启动时先检查设备是否具备该能力
- 不具备时，拍照导入入口给出"请改用粘贴文本"的明确提示
- **其余功能（文本导入、检索、管理）完全不受影响**

**设计原因**：在鸿蒙平台上，若应用静态引用设备不具备的 AI 能力模块，会导致**应用在启动阶段直接终止**，而不是功能不可用。因此核心算法模块与设备能力解耦，是保证应用可启动的必要条件。

### 5.6 增量删除与索引压缩

删除资料时采用**标记删除**而非立即重建索引：

- 删除只与该资料的片段数成正比
- 被删除片段在检索时跳过
- 标记比例超过 20% 时自动执行物理压缩

**实测对比**（1,000 份资料库删除 10 份）：

| 方式 | 耗时 |
|---|---|
| 立即重建索引 | 7,322 毫秒 |
| **标记删除** | **7.6 毫秒** |

### 5.7 存储容错

资料以 JSON 格式持久化。读取时**逐条校验**，遇到损坏条目跳过并继续，而非整体失败。

**设计意图**：一份存档中某一条损坏，不应导致用户失去其余全部资料。读取结果返回被跳过的条数。

## 六、数据结构

### 6.1 主要数据结构

| 结构 | 含义 |
|---|---|
| `DocItem` | 一份资料：标识、标题、来源类型、位置、入库时间、全文 |
| `Chunk` | 一个可检索片段：标识、所属资料、序号、原文起止位置、文本 |
| `Hit` | 一条检索命中：片段、相关度得分、命中的词项、高亮区间 |
| `ScoreDiagnostics` | 候选得分统计：候选数、最高分、均值、标准差、最大落差及位置 |
| `BudgetInput` | 资源预算输入：可用时间、可用内存、电量 |
| `SearchResult` | 检索结果：命中列表、实际条数、条数来源、诊断信息 |

### 6.2 持久化格式

```json
{
  "version": 1,
  "docs": [
    {
      "id": "d1",
      "title": "示例资料",
      "source": "note",
      "uri": "note://...",
      "addedAt": 0,
      "text": "正文内容……"
    }
  ]
}
```

**说明**：只持久化资料本身，**不持久化倒排索引**。启动时从资料重建索引——个人资料量级下重建为秒级，且避免了索引格式变更导致旧存档失效。

## 七、错误处理

| 情况 | 处理方式 |
|---|---|
| 输入为空 | 提示"内容不能为空"，不入库 |
| 设备不支持 OCR | 提示改用粘贴文本，其余功能正常 |
| OCR 识别置信度过低 | 拒绝入库并提示原因 |
| OCR 识别置信度中等 | 允许入库，但提示建议重拍 |
| 存档中部分条目损坏 | 跳过损坏条目，保留其余，返回跳过数量 |
| 检索无结果 | 显示"没有找到相关内容"，不报错 |
| 资料库为空时检索 | 提示先添加资料 |
