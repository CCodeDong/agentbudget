### 识别质量对照

| 原文 | 识别结果 | 差异 |
|---|---|---|
| 第三章  预算感知调度 | 第三章 预算感知调度 | 空格归一化 |
| 移动端的多智能体系统存在一个矛盾： | ...存在一个矛盾: | 全角冒号 → 半角 |
| ...消耗一倍 token， | ...一倍token, | 全角逗号 → 半角；空格丢失 |
| ...只有四千到八千。 | 一致 | — |
| 工具注入深度 → 检索置信度 | 工具注入深度 检索置信度 | **箭头 → 完全丢失** |
| 消息形式     → 信息预算 | 消息形式 / 信息预算（分成两行） | **箭头丢失 + 换行** |
| BM25 ranking is statistical. | 一致 | — |

**一句话总结：正文识别得很准，但符号类内容会丢。**
箭头 `→` 全部丢失，全角标点被归一化为半角。

### 这对研究意味着什么

项目主张"感知环节要用识别置信度作信号"。这次实测说明：

- Vision Kit **不返回标量置信度**，只返回文本块
- 所以"置信度"必须由我们自己估计（块数、字符数、标点完整度等）
- **符号丢失是一个可检测的失败模式**：如果原文有箭头而结果没有，
  说明这一块可能不可靠

> ⚠️ **诚实说明**：当前代码里的 confidence 是个粗糙代理
> （`blockCount >= 3 ? 0.9 : 0.7`），**不是真实的概率**。
> 它只能驱动"收下/重拍/丢弃"的粗分档，不能用于精细排序。

## 三、这次验证证明了什么 / 没证明什么

**证明了**：
- 真实 CoreVisionKit OCR 在该设备上**可调用且返回正确结果**
- 静态导入 CoreVisionKit **不会**导致加载期崩溃（与 A2A 形成对照）
- 端到端：图片 → PixelMap → OCR → 文字，全链路通

**没证明**：
- 相机拍照路径（未接入，用的是内置图）
- 真实纸质文档/手写的识别率
- 低质量图片下的表现（这正是 OcrQualityPolicy 的用武之地，但没测）
- 手机形态上的表现（这台是 2in1）
