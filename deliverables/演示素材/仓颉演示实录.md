# 仓颉调度器演示实录

> 本文件由 `tools/demo_run.py` **实际执行并捕获输出**生成，不是手工抄写。
> 重跑该脚本即可得到与本机一致的结果。

> 引擎：`projects/agentbudget4cj/bin/agentbudget4cj.exe` （11,751,424 字节）

### 1. 三层放置：降级方向保住边缘执行

同一任务、同一预算（已用 75%），只改网络档位。三层各自显现：

| 网络档 | 预期 | 依据 |
|---|---|---|
| wifi | cloud | 广域网可用 ∧ 难度≥0.6 ∧ 预算余量<80% |
| weak_lan | **edge** | 广域网不可用，**但局域网边缘仍可达** |
| weak_nolan | device | 既无广域网也无局域网 |

**第 2 行是演示的关键**：把「广域网不可用」等同于「无远程选项」的基线
会在这里全部退回设备，而调度器保住了边缘执行。


```
网络档         route      msgForm     toolStrategy      k   理由
wifi           cloud      structured  two-stage-top3     3  hard step, wide-area viable, headroom left
weak_lan       edge       structured  two-stage-top3     3  wide-area weak unusable; LAN survives
weak_nolan     on-device  structured  two-stage-top3     3  no remote tier viable
```

### 2. 自适应 top-k：信号来自检索，不是预算

得分驱动的自适应策略：**对查询歧义敏感，对预算不敏感**。

注意第 3 条查询——它与此前实验中「零字面重叠」的歧义查询相同，
策略正确识别出信号缺失并回退到固定值。

对照：把 k 绑定到 token 预算的版本在同一预算下会给所有查询**同一个 k**，
且实测被每一个固定 k 支配。


```
查询                                          kUsed   选中工具
search my files for the quarterly report         3   file.search,web.search,battery.status,
look up a contact named Li Wei in my address     2   contact.lookup,clipboard.read,
find online the release notes for the new ve     5   calendar.create,contact.lookup,file.sear

同一查询、不同预算（kUsed 应当不变）：
  预算已用 7000   -> kUsed=3
  预算已用 4000   -> kUsed=3
  预算已用 7900   -> kUsed=3
```

### 3. 三种选择器：为什么信号选错了就会输

同一查询、同一预算，只改选择器。

这正是论文 §6.6→§6.7 的正负一对实验在命令行上的样子：
预算驱动的策略看起来也「在工作」（给出了一个 k），但它实测被固定值支配；
得分驱动的策略则在完整评测中支配了每一个固定 k。


```
选择器                含义                         结果
得分驱动（-50）            本项目的提案                       two-stage-top3  工具 tokens=418
预算驱动（0）              负面结果：被固定 k 支配                two-stage-top6  工具 tokens=671
固定 k=3               基线                           two-stage-top3  工具 tokens=418
固定 k=5               基线                           two-stage-top5  工具 tokens=594
```

### 4. 消息表示：结构化编码同时赢得成本与正确性

同一个负载，三种渲染。`structured` 最短且**无损**；
`summary` 在 40 字符下截断了负载——这正是它在多跳链上必然失败的原因：
第二条消息的载荷是第一条的回显，比第一条长约一倍，
而定长前缀自己就吃掉了整个预算（论文 §3.3.1 给出跳数阈值公式）。


```
形式          渲染结果                                                      token
natural       Agent planner is sending the following instruction to agent    28
summary       [planner->executor] instruction: {"query": "quarterly report   18
structured    planner|executor|instruction|{"query": "quarterly report", "   17
```

### 5. 工具池规模：可复现性为什么是硬要求

`pool` 动词把工具池限制到前 N 个，使早期的 5 工具实验**可由命令复现**——
而修复前的数据与修复后的数据**不可比较**。这一点曾导致论文一条核心结论出错
（跨两套检索实现比较），详见 `docs/07`。


```
工具池   选中工具                                         工具 tokens
5 个       file.search,web.search,calendar.create,            345
15 个      file.search,web.search,battery.status,             418
```
